### 概要
ユーザーからのフィードバックに基づくデバイスモニタ画面の表示・操作不具合の改修（Issue #58, Issue #60）、実機環境の画面キャプチャを収録した包括的なユーザーマニュアルの作成・公開、および GitHub Actions CI におけるテスト実行パイプラインの正常化（Playwright E2E テストの統合と依存パッケージインストール）を実施。

### 作業内容詳細

#### 1. デバイスモニタにおける複数アドレス・デバイス監視不具合の修正 (Issue #58, PR #59)
- **背景と課題**:
  - デバイスモニタで異なるデバイス種別やアドレスを追加した際、種別タブの排他フィルタリングにより既存のデバイスが表示上消去され、「上書きされて1つのデバイスしか見えない」「先に登録したものが書き換わってしまう」問題が発生していた。
- **改修内容**:
  - 全デバイスを同時に同一テーブルで一覧監視できる **「ALL（すべて）」タブ** を新設し、デフォルトの選択状態に設定。
  - 「ALL」タブ選択時は、入力フォームの「Device」ドロップダウンを変更してもフィルタタブが強制切り替えされないよう分離。
  - 「Points（点数）」入力項目を追加し、開始アドレスから連続する複数アドレス（例: D100〜D104）を一括登録できる機能を提供。
  - 同一の `(device, address)` に対する再追加時の重複防止（フォーマット更新へ統合）および Address/Points 入力欄での Enter キーによる即時追加を実装。
- **テスト拡充**:
  - `ALL` タブでの複数種別（D と M 等）の同時一覧表示、種別タブ（D, M）切替時の適切なフィルタリング、Points 指定による連続アドレス登録、同一アドレス再登録時の重複防止をテストで検証。

#### 2. デバイスモニタの「Clear All」機能の修正 (Issue #60, PR #61)
- **背景と課題**:
  - 「Clear All」ボタンを押した際、PLC メモリのゼロクリアのみが行われ、画面上の監視行（テーブル一覧）が消去されず「なにも消えていない」状態になっていた。
- **改修内容**:
  - `Clear All` 実行時に監視リスト配列（`this.devices`）を空にし、テーブルを初期状態（「No devices monitored. Add one above.」）に戻すよう修正。
  - デバイスメモリ一括初期化 API（`POST /api/devices/clear`）の連動を維持。
  - 日本語（「監視リストとデバイスメモリを初期化しますか？」）および英語（「Clear all monitored devices and memory?」）の確認ダイアログを表示し、キャンセル時は既存の監視行を保持。
- **テスト拡充**:
  - Clear All 実行による監視行の全削除とメモリ値ゼロ化、クリア後の新規デバイス再登録、ダイアログキャンセル時の保持をテストで検証。

  - 概要、クイックスタート、各画面の詳細機能解説、実践テストシナリオ（SCADA結合テスト、遅延・タイムアウト耐性テスト、自律走行テスト）、REST API 一覧、トラブルシューティング（FAQ）を網羅。

#### 4. GitHub Actions CI の修正と安定化
- **背景と課題**:
  - Playwright ブラウザ（Chromium）を起動するテストが単体テスト実行ファイル（`test_clear_all_monitor.py`, `test_device_monitor_multi_address.py`）として配置されていたため、CI 上の「Run unit tests」ステップ（Playwright ブラウザインストール前）で `BrowserType.launch: Executable doesn't exist` エラーが発生し、CI が失敗していた。
- **改修内容**:
  - Playwright を使用する全ブラウザテストを、E2E 専用テストファイル `tests/test_e2e.py` に統合。
  - 不要となった単体テストファイルを削除し、`uv run pytest`（単体テスト）実行時はブラウザを起動せず高速・安定に完走する構成を維持。
  - `.github/workflows/ci.yml` の Playwright インストールコマンドに `--with-deps` を追加（`uv run playwright install --with-deps chromium`）し、Ubuntu ランナー環境に必要な OS ライブラリを確実に導入。
  - テスト起動時のポート競合防止のため、テストコード側でエフェメラルポート（`port=0`）の自動割り当てを徹底。

#### 5. スクリプトエディタでの未保存記述からの直接Start対応 (Issue #62, PR #63)
- **背景と課題**:
  - エディタ上で直接 YAML を新規記述して「Start」ボタンを押しても、事前に「Save」をクリックしてディスクに保存していない場合はサーバ側で 404（Script not found）となり、ステータスが `running` に遷移しない問題があった。
  - また、スクリプト名が未入力の場合に無反応になっていた。
- **改修内容**:
  - スクリプト名が未入力の場合は自動的にデフォルト名（`untitled.yaml`）を割り当て、拡張子省略時も `.yaml` を補完。
  - 「Start」ボタン押下時にエディタ上の現在の編集内容を自動保存（Auto-save）したうえでスクリプトエンジンを即時起動するよう改善。
  - バックエンド API（`POST /api/scripts/{name}/start`）にてリクエストボディによるスクリプト内容の直接受信・保存・起動に対応。
  - テンプレート読込以外の自作スクリプトでも、エディタに書いた内容が直接ワンクリックで `running` 状態になるシームレスな操作性を確立。
